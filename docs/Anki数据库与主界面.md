# Anki 数据库与主界面改造说明

> 这一轮做了两件大事：**本地库换成 Anki 的原生数据库**，**主界面改成 Anki 式的五入口结构**，
> 并补上了演示模式（课堂投影）、统计页与导出页。

## 一、为什么换成 Anki 的数据库

之前用的是 sembast（一个 JSON 文件的 NoSQL 库）。它能用，但和 Anki 生态完全不通。
现在直接把 Anki 的原生格式当作应用的存储：

- **可以直接用 Anki 打开**：库文件就叫 collection.anki2，放在应用数据目录里
- **复习历史进 revlog**：Anki 自己的统计数据能直接用
- **导出即互通**：导出页能生成一份 .anki2，拿 Anki 打开就能看到卡片
- **将来做 .apkg 导入导出**不用另起炉灶

### 为什么用 schema 11 而不是 18

Anki 有新旧两套 schema：

| | schema 11（本应用用的） | schema 18（新版 Anki 内部） |
|---|---|---|
| 配置文件 | col 表里存 JSON 文本（models / decks / dconf / conf） | 拆成 notetypes / fields / templates / decks / config 等表，配置是 protobuf blob |
| Anki 能打开吗 | 能，打开时会自动升级成 18 | 只有新版 Anki 能开 |
| .apkg 里常见吗 | 是（老版本导出的都是它，genanki 也生成它） | 新版导出的 .apkg 是它 |

schema 11 用 JSON 存配置，没有 protobuf 编解码的负担，Anki 又完全认；
所以本次先落 schema 11，把数据互通跑通。将来要支持读新版 .apkg，
再补一个 protobuf 读取层即可，表结构不用动。

## 二、表结构

### Anki 原生表（完全按官方 schema 11 建）

| 表 | Anki 里的含义 | 本应用怎么用 |
|---|---|---|
| col | 集合元信息与全部配置 | ver=11、crt；models 里放「单词卡」笔记类型，decks 里放牌组 |
| notes | 笔记（内容） | 一张卡片 = 一条 note |
| cards | 卡片（复习状态与所属牌组） | 与 note 一一对应，ord=0 |
| revlog | 复习历史 | 每次作答写一条 |
| graves | 删除墓碑（同步用） | 删卡片时写 |

### 应用自己的扩展表（wc_ 前缀）

Anki 会忽略不认识的表，所以可以和它安全地共处一个文件：

| 表 | 为什么需要 |
|---|---|
| wc_card_ids | **Anki 的主键必须是整数**，而应用内部用字符串 id（uuid）；这张表保持两边干净，Anki 的表里只有整数 id |
| wc_deck_ids | 同理，牌组的字符串 id 对 Anki 整数 id（默认牌组固定映射到 Anki 的 Deck 1） |
| wc_card_stats | Anki 没有「答对次数 / 掌握度 / 累计反应时间 / 创建时间」这些列 |
| wc_answer_log | 完整答题流水：选了什么、正确答案、是否超时、哪一轮测验（revlog 放不下这些） |
| wc_settings | 应用自己的配置（API Key、主题、限时等），不塞进 Anki 的 col.conf |

## 三、字段映射

notes.flds 按固定顺序用 \x1f 拼起来（Anki 的约定）：

```
单词 | 释义 | 音标 | 例句 | 词性 | 备注 | 干扰项
```

- sfld = 单词；csum = sha1(sfld) 前 8 位十六进制，和 Anki 的算法一致
- tags 存卡片来源（手动导入 / API 生成），在 Anki 里一眼能看出来
- cards 的 ivl / factor / reps / lapses / due / type / queue 跟着学习状态走，
  新卡 type=queue=0，复习过的卡 type=queue=2
- revlog 的 ease 用 Anki 的语义：**1 = Again（答错或超时），3 = Good（答对）**；
  time 是反应毫秒；ivl / lastIvl 记新老间隔

## 四、从旧库迁移

启动时如果发现旧的 word_cards.db 且新的 Anki 库里还没有卡片，
就把卡片、答题记录、牌组、配置一次性搬过去，然后把旧文件改名成 word_cards.db.migrated，
不会重复导入。

## 五、主界面：入口按平台给（桌面五个 / 手机四个）

上方一排，桌面端**五个**：**加入 / 作答 / 演示 / 统计 / 导出**；
手机端**四个**：**加入 / 作答 / 统计 / 导出** —— 课堂投影是「一台电脑接投影仪」的场景，
手机既开不了独立的演示窗口，也没法把画面投给一屋子人，所以「演示」整页不给
（入口、页面、设置页里那套演示深浅色一起不出现）。

判定只有一处：`home_shell.dart` 的 `visibleHomeTabs()`；主壳记的是**页面 id**
（`home_tab` 存的就是它）而不是下标，所以手机端少一个入口也不会整体错位。
设置里的值照旧留着：在手机上记着「演示」，打开时退回默认的作答页，换到桌面端还是演示页。
页面是懒加载的，没点进去的页不构建。

| 入口 | 能力 |
|---|---|
| **加入** | 手动加一张卡（单词 / 释义 / 音标 / 词性 / 例句 / 备注 / 干扰项）；干扰项不够 4 个会自动从同词库补齐；同名卡片会提示并更新内容；另有「粘贴 JSON 批量导入」与「卡片管理」 |
| **作答** | 学习概览、题量快捷键、每题限时与显示时机一览、开始测验、**只练做错过 / 正确率低的词** |
| **演示**（仅桌面端） | 把题放大到全屏给学生答：每题停留秒数（只有输入框）、选项编号 12345 / ABCDE、随机顺序、循环播放、每轮重新打乱选项、翻页提示音（内置正弦波可调，也可自选音频）、答案 txt 的输出模式与目录 |
| **统计** | 总览（含平均反应时间）、掌握度分布、最近七天柱状图、最需要加强的词、最近答题 |
| **导出** | 卡片 JSON、答题记录 CSV、**Anki 数据库**、复制卡片 JSON 到剪贴板 |

## 六、演示模式（课堂投影，仅桌面端）

演示**不是背诵，是用来答题的**：和作答页看到的是同一种题（一个单词 + 五个选项），
只是放大到全屏，而且**屏幕上点不了** —— 学生口头作答，讲的人控制节奏。
手机端没有这个功能，连入口都没有（见上一节）。

**全程不显示答案** —— 屏幕上连「揭晓」按钮都没有，答案只在结束后的 txt 里。

铁律和测验一致：**每道题都有停留限时，到点直接换下一题**，没有「不限时」。

- 出题直接复用测验的 buildQuizQuestions，选项数量、去重、干扰项补齐的规则完全一致
- 计时用 1 秒一跳的定时器 + 累加计数（不是 DateTime.now()），
  这样 widget 测试里的假时钟也能驱动它
- 暂停时**不扣时间**；继续后从暂停处接着走
- 不循环时放完最后一题就进入结束页，可以「再来一遍」
- 全屏页：空格暂停/继续，左/右方向键上一题/下一题，Esc 退出
- 独立窗口开不出来时（插件不可用、测试环境）退回应用内全屏页，行为一致
- 选项前有编号，**可以是 12345 也可以是 ABCDE**，学生按编号喊答案
- **每轮重新打乱选项**（默认开）：循环到下一轮时重新出一次题，
  选项顺序重排，防止学生记住「答案永远是第三个」
- 演示是纯展示：wc_answer_log 与 Anki 的 revlog 都不会被写，卡片掌握度也不会动

### 演示答案 txt

一轮演示结束时（不循环放完了，或者中途 Esc 退出）写一份 txt：

- 文件名 = 演示答案_时间_卡组名.txt，例如 演示答案_20261015_223448_考研词汇.txt
- **两种输出模式**：
  - 只含选项：一行一题，只写正确答案那一项
  - 单词 + 义项：写单词、音标和正确答案
- 输出目录可以在演示页直接填，也能用系统选目录对话框挑；
  默认是系统文档目录下的 word_cards_answers（这台机器的文档被重定向到 D 盘也照常工作）
- 同一个 session 只会写一次（中途退出和正常结束不会写两份）
- 写失败不影响演示收尾，但会把原因显示在演示页上

### 翻页提示音：可以换

默认是 **3000 Hz、0.5 秒**的正弦波，但频率与时长都能在设置里改（100-15000 Hz / 20-3000 毫秒），
也可以直接换成用户自己的音频文件。

- 内置波形是**运行时现算**的：44.1 kHz、单声道、16 位 PCM，包成 wav 再播；
  仓库里不带任何音频资源文件
- 首尾各有 12 ms 淡入淡出，避免爆音
- 500 ms 时长的采样数是 22050；单测直接检查 WAV 文件头与采样数，
  还用**过零次数**验证了它真的是 3000 Hz（0.5 秒 1500 个周期，约 3000 次过零）
- 自选音频走系统文件选择器（file_selector），路径存在设置里；
  **文件读不到时自动退回内置提示音**，讲课时不会突然没声音
- 提示音的开关在「演示」页；**关掉就完全不创建播放器**
- 音频不可用（没有设备、插件异常）时静默降级成无声，绝不打断演示

## 七、统计与导出

- 统计的派生数据由一个纯函数 computeBreakdown 算出来，方便单测：
  掌握度分布、最近 N 天分桶、按正确率排序的最弱词、平均反应时间
- **投影模式的记录一律不计入**统计，和 computeStats 保持一致
- 导出走 VACUUM INTO 而不是复制文件：WAL 模式下最近的写入可能还在 -wal 里，
  直接复制会丢数据，VACUUM 出来的是一份完整干净的库
- 导出的卡片 JSON 用的是导入器认得的那套字段，所以「导出 - 再导入」是闭环的

## 九、这一轮修掉的坑

1. **Riverpod 不允许在 widget 生命周期里改 provider**：演示页原来在 dispose() 里
   调 stop()，真机端到端直接抛断言。改成路由返回之后再停。
2. 测试容器不销毁会留下定时器，testWidgets 结束时报
   「A Timer is still pending」；改成每个用例结束一定销毁容器。
3. sqlite3 的 Row 没有 asMap()（它自己就是个 Map），
   用 Map<String, Object?>.from(row)。
4. sqlite3 的 Database.dispose() 已废弃，改 close()。
5. main.dart 第一次写错了位置（写到了仓库根目录），analyze 报 Target of URI doesn't exist。
6. 端到端里从「加入」页发起导入后，壳子停在「加入」，
   回首页后要先切到「作答」才能看到概览，测试里补了这一步。
7. 统计页的「最需要加强的词」在折叠线以下，ListView 是懒构建的，
   测试里得先滚过去才能断言。

## 十、后续补上的三件事（标签 / 语言 / FSRS）

### 1. 标签与语言都写进 notes.tags

Anki 的标签本来就是「一条笔记可以有多个标签」，正好拿来表示语言的语种和用户的分类：

```
tags = ' 手动导入 lang::ja N2 第1课 '
        └ 来源    └ 语言      └ 用户标签
```

- 来源沿用原来的 `手动导入` / `API 生成`
- 语言用 `lang::xx`（en / fr / ja / ko / ru）——在 Anki 里一眼能看出这张卡是什么语言的词
- 用户标签就是普通标签；写入前会把空白换成下划线（Anki 的标签不能带空格）

### 2. FSRS 的记忆状态单独一张表

`wc_card_fsrs`（uid / stability / difficulty / reps / lapses / state / last_review_at / due_at）
和 `wc_card_stats`（掌握度、正确率、interval_days、ease_factor）**完全分开**：

- 打开 FSRS 时只写 `wc_card_fsrs`，原有的那套字段照旧由原来的逻辑维护
- 换回「原有算法」时 `wc_card_fsrs` 原样保留，不删不改
- 卡片模型上就是 `WordCard.fsrs` 这个可空字段，读不出来就是 null（没进过 FSRS 调度）

### 3. wc_settings 里新增的配置键

`projection_theme_mode`（演示模式单独的深浅色）、`active_deck_id`（当前卡组）、
`language`（新词默认语言）、`scheduler_mode`（原有算法 / fsrs）、
`fsrs_desired_retention`（目标保留率）、`prompt_template_id`（上次用的 Prompt 模板）、
`home_tab`（上次停在哪个页面）、`study_tag_filter`（作答范围里的标签筛选，多选取「与」）。
旧库读不到这些键时各自有默认值，不需要迁移。顺带改了 `quiz_question_count` 的含义：
**0 表示「全部」**（`AppSettings.allQuestions`），不再是「取一个够大的数字」。
这里做了一次**一次性迁移**：还没有 `study_tag_filter` 键的老设置块里，
`quiz_question_count = 10`（旧默认值）重新解释成「全部」，用户主动选过的 5 / 20 照旧尊重；
只要保存过一次设置，新键就写进去了，这件事不会再来第二次。

### 5. 这一批踩到的坑

1. **第二个引擎里没有 window_manager**：desktop_multi_window 起的子窗口只注册了它自己的通道，
   `window_manager` 的调用会抛 MissingPluginException。改成直接调 user32.dll
   （按窗口类名 `FLUTTER_MULTI_WINDOW_WIN32_WINDOW` 找到子窗口，再 ShowWindow / PostMessage）。
2. **对话框里的 TextEditingController 不能在 showDialog 返回后立刻 dispose**：
   退场动画还在跑，会报「A TextEditingController was used after being disposed」。
   把它交给对话框自己的 State 管理。
3. **测试环境里的平台通道会卡住**：不但抛异常，还可能是永远不完成的 Future。
   于是多窗口这条路只在 `supportsPresentationWindow()` 为真时才走
   （桌面系统 + 不在 flutter test 里），失败还有 6 秒超时兜底。
4. **TextStyle 的 fontSizeFactor 断言**：`TextTheme.apply(fontSizeFactor:)` 要求每个样式都有字号，
   演示主题改成只统一颜色，字号由显式的 projectionStyle 给。
5. **字符串里的换行**：写文件时 `\n` 写成了 `\\n`，界面上真的显示了「\n」两个字，
   已修（演示结束提示）。
