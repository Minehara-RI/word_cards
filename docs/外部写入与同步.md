# 外部写入与设备同步

这是两条**方向相反**的链路，各占一个端口，可以只开一条：

| | 外部写入（AnkiConnect 兼容） | 设备同步 |
|---|---|---|
| 方向 | 别的程序 → 本应用 | 本应用 ↔ 本应用 |
| 谁发起 | Yomitan / 脚本 / AI agent | 你点「开始同步」 |
| 默认端口 | 8765 | 8766 |
| 默认监听 | 只听 `127.0.0.1` | 局域网（开了开关之后） |
| 鉴权 | 访问口令（`key`） | 同步口令 |
| 数据去向 | 只写词，不改已有卡片 | 整库交换，双向合并 |

> 两个服务都只在**应用运行时**监听。手机切到后台被系统冻结后端口就不响应了 ——
> 这是刻意不做前台服务的取舍：同步是「想起来才点一下」的事，不值得常驻一条通知。

## 一、外部写入（AnkiConnect 兼容）

### 为什么是这个协议

AnkiConnect 是 Anki 的插件，线格式就是「POST 一个 JSON、回一个 JSON」，没有跟 Anki 的内部实现绑定。
Yomitan（浏览器划词查词）这类工具已经把它当成事实标准，所以本应用直接在**服务端**实现这套协议：
插件那边一行配置都不用改，把地址指过来就能用。

### 怎么开

设置 →「外部写入（AnkiConnect 兼容）」：

1. 打开「启用」；
2. 端口默认 8765。**如果本机装了 Anki，先关掉它或把这里改成 8766**，否则端口会撞；
3. 想在手机上被别的设备写，打开「允许局域网访问」，并务必设一个访问口令；
4. 「目标卡组」默认跟随客户端；想固定收词位置就选一个卡组，客户端的 `deckName` 会被忽略；
5. 「顺手用 AI 补全干扰项」默认关 —— 外部写入要快，不该被一次模型调用拖住。

### Yomitan 怎么配

Yomitan 设置 → **Anki** → 勾选「启用 Anki 集成」：

- **AnkiConnect URL**：填 `http://127.0.0.1:8765/`（手机或别的机器上填 `http://<这台设备的 IP>:8765/`）；
- **API key**：本应用设了口令就填同一个；
- **Deck**：选一个卡组名（会出现在下拉里；不存在的话 Yomitan 会先创建）；
- **Model**：选 `单词卡` 或 `Basic`；
- **Fields**：把「Expression / 释义 / 音标 / 例句」映射到字段上。

映射好之后，划词 → 加卡，应用里立刻能看到这张卡（列表是通过数据库变更通知刷新的）。

### 支持的动作

`apiReflect` 只报下面这些。**没列出来的一律不实现，也不谎报** ——
客户端会据此把「浏览」「编辑」「音频」这些按钮藏起来，而不是等你点下去才报错。

| 动作 | 用途 |
|---|---|
| `version` | 返回 6 |
| `apiReflect` | 能力查询（返回请求动作与已实现动作的交集） |
| `multi` | 一次发多个动作 |
| `requestPermission` | 问「要不要口令」；**这一项不校验口令**，否则客户端连门都敲不开 |
| `deckNames` / `createDeck` | 卡组名与建卡组 |
| `modelNames` / `modelFieldNames` | 模型与字段 |
| `canAddNotes` / `canAddNotesWithErrorDetail` | 预检（不写库、不建卡组） |
| `addNote` / `addNotes` | 写卡 |
| `notesInfo` / `findNotes` | 回读 |
| `updateNoteFields` | 改字段 |

**不做的**：`guiBrowse`、`guiEditNote`、`storeMediaFile`、`suspend`、`sync`、
`findCards`、`cardsInfo`。其中 `sync` 尤其不能假装成功：那会让用户以为数据已经同步到 AnkiWeb 了。

### 模型与字段

物理上只有一张笔记类型「单词卡」（7 个中文字段：单词 / 释义 / 音标 / 例句 / 词性 / 备注 / 干扰项）。
协议层额外认一个 `Basic`（Front / Back），映射到「单词 / 释义」。

模型名记在 `notes.data` 这个 JSON 列里（Anki 不读它，我们的模板也不读），
所以 `notesInfo` 能原样回读「这张是当 Basic 写进来的」。
字段名同时收中英文别名（Front / Word / Expression / 单词…），客户端按哪套配的都能对上。

### 查重与错误串

- 默认查重（`allowDuplicate` 为假），范围看 `options.duplicateScope`：整个词库或只在目标卡组；
- 重复时返回 **`cannot create note because it is a duplicate`** —— 这是 Anki 的原话，
  Yomitan 会把它显示成「重复卡片」；
- 不认识的动作用 **`unsupported action`**（客户端靠这个字符串判断「没这个功能」）；
- 找不到模型/卡组分别是 `model was not found: X` / `deck was not found: X`。

### 写进来的词能不能考

五选一需要 4 个干扰项，而外部工具通常只给「词 + 释义」。所以：

1. 先按客户端给的字段解析；`干扰项` 字段有就用；
2. 不够就从**同卡组**已有释义里借；
3. 还不够就挂 `待补全` 标签（卡片列表里能直接看到），
   打开「顺手用 AI 补全」的话会异步补一次，补够自动摘掉标签。

写入来源记成 `外部写入`，在卡片上表现为一个 Anki 标签，统计里也能区分。

### 线格式（自己写脚本时看这里）

```bash
curl -s http://127.0.0.1:8765/ -H 'content-type: application/json' -d '{
  "action": "addNote",
  "version": 6,
  "params": {
    "note": {
      "deckName": "默认词库",
      "modelName": "Basic",
      "fields": {"Front": "harbor", "Back": "n. 港口"},
      "tags": ["lang::en"]
    }
  }
}'
```

- `version >= 5` 的响应是 `{"result": …, "error": null}`；
- `version < 5`（Yomitan 发的是 2）的响应**就是裸结果**；
- 动作失败返回 `{"result": null, "error": "…"}`，**HTTP 仍然是 200**；
- 口令不对返回 HTTP 403。

## 二、设备同步

### 怎么用

两台设备在同一个局域网里：

1. 至少在一台上打开「在这台设备上监听」；
2. 在另一台的「设备同步」页填上对方的地址（页面上会列出本机地址，照着念即可）和同一个口令；
3. 点「开始同步」。

同步完两端的卡片、卡组、答题记录就都一样了。**每台设备各自同步一次**，不需要「主设备」。

> 只开一台的监听也能同步：发起方先把自己的数据推上去，对方合并之后再传回来，
> 一次往返两端就收敛了。两台都开只是让两边都能当发起方。

### 合并规则

| 数据 | 谁说了算 |
|---|---|
| 卡片内容（单词、释义、干扰项、标签、语言…） | `updatedAt` 更晚的那次编辑；同一毫秒再按内容字典序，保证可复现 |
| 学习进度（复习次数、掌握度、FSRS） | 最后一次复习更晚的那一端 |
| 答题记录 | 按 id 取并集（id 是 uuid，重复插入无副作用） |
| 删除 | `wc_tombstones` 里的删除时间：不早于最后修改时间才算删掉 |

几个刻意的选择：

- **进度与内容分开合**。答一次题会改进度但不改 `updatedAt`（否则每答一次都像「内容变了」），
  所以两件事用两个时间轴；
- **删除与修改比时间**：删了之后又改过的卡会回来。这是「误删能救回来」的代价，
  比「永远删掉」更符合直觉；
- **卡组被删，卡不跟着消失**：两边都把卡退回默认卡组，和界面上「删除卡组」的行为一致；
- **整库交换，不做增量**：整库现在只有几 MB，一次传完最省事，也不会出现「日志丢了导致对不上」。

### 为什么不用 Anki 自己的同步

Anki 的同步协议是 protobuf + hostKey + 一堆服务端状态，自己实现要几周；
两台的 `collection.anki2` 又不能直接覆盖（整数 id 是设备本地的，WAL 模式下还会丢最近的写入）。
更实际的一点：我们的进度有一部分在 `wc_` 扩展表里，Anki 的同步器根本不知道它们。

### 限制

- **同一个局域网**。跨网段、走公网都不行（没有中继，也不打算做）。
- **应用要在前台**。手机切后台后系统会冻结进程，端口不再响应。
- **Windows 第一次监听会弹防火墙提示**，要选「允许」。
- **没有自动发现**：不引 mDNS，避免安卓的组播权限与权限弹窗；地址手动填一次。

## 三、排错

| 现象 | 先看什么 |
|---|---|
| Yomitan 说连不上 | 应用里开关开了没？端口是不是被 Anki 占了（8765）？口令对不对？ |
| 手机上连不上电脑 | 电脑防火墙放行了吗？两台在同一个 Wi-Fi 吗（很多路由器有「访客网络」隔离）？ |
| 同步说「口令不对」 | 两边填的是同一个字符串吗（区分大小写） |
| 同步完没变化 | 看页面上的结果条：可能是「两边本来就一样」。真的少了词，看那张卡是不是被对面删了 |
| 删掉的词又回来了 | 它一定在另一台上被改过，而且修改时间晚于删除时间。再删一次即可 |
| 手机端端口没反应 | 应用被切到后台了，回到前台再试 |
