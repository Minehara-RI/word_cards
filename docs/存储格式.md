# 存储格式

应用把数据放在一个 **Anki 原生库**里：`collection.anki2`（SQLite，schema 11）。

| 平台 | 路径 |
|---|---|
| Windows | `%APPDATA%\com.minehara\word_cards\collection.anki2` |
| Android | 应用数据目录下的同名文件 |

除了 Anki 自带的表，另有几张以 `wc_` 开头的扩展表和它共处一个文件 ——
Anki 会忽略不认识的表，所以两边可以安全共存。

## 为什么用 Anki 的原生格式

- **可以直接用 Anki 打开**库文件；
- **复习历史进 revlog**，Anki 自己的统计数据能直接用；
- **导出即互通**：导出页能生成一份 `.anki2`，拿 Anki 打开就能看到卡片；
- 将来做 `.apkg` 导入导出不用另起炉灶。

### schema 11 而不是 18

| | schema 11（本应用用的） | schema 18（新版 Anki 内部） |
|---|---|---|
| 配置文件 | `col` 表里存 JSON 文本（models / decks / dconf / conf） | 拆成 notetypes / fields / templates / decks / config 等表，配置是 protobuf blob |
| Anki 能打开吗 | 能，打开时会自动升级成 18 | 只有新版 Anki 能开 |
| `.apkg` 里常见吗 | 是（老版本导出的都是它） | 新版导出的 `.apkg` 是它 |

schema 11 用 JSON 存配置，没有 protobuf 编解码的负担，Anki 又完全认。
将来要支持读新版 `.apkg`，再补一个 protobuf 读取层即可，表结构不用动。

## 表结构

### Anki 原生表（按官方 schema 11 建）

| 表 | Anki 里的含义 | 本应用怎么用 |
|---|---|---|
| `col` | 集合元信息与全部配置 | `ver = 11`、`crt`；`models` 里放「单词卡」笔记类型，`decks` 里放牌组 |
| `notes` | 笔记（内容） | 一张卡片 = 一条 note |
| `cards` | 卡片（复习状态与所属牌组） | 与 note 一一对应，`ord = 0` |
| `revlog` | 复习历史 | 每次作答写一条 |
| `graves` | 删除墓碑（同步用） | 删卡片时写 |

### 应用扩展表（`wc_` 前缀）

| 表 | 为什么需要 |
|---|---|
| `wc_card_ids` | **Anki 的主键必须是整数**，而应用内部用字符串 id（uuid）；这张表保持两边干净，Anki 的表里只有整数 id |
| `wc_deck_ids` | 同理，牌组的字符串 id 对 Anki 整数 id（默认牌组固定映射到 Anki 的 Deck 1） |
| `wc_card_stats` | Anki 没有「答对次数 / 掌握度 / 累计反应时间 / 创建时间」这些列 |
| `wc_answer_log` | 完整答题流水：选了什么、正确答案是什么、是否超时、属于哪一轮测验（revlog 放不下这些） |
| `wc_card_fsrs` | FSRS 的记忆状态（稳定性 / 难度 / 到期时间等） |
| `wc_api_cache` | API 直连的生成缓存 |
| `wc_settings` | 应用自己的配置，不塞进 Anki 的 `col.conf` |

## 字段映射

`notes.flds` 按固定顺序用 `\x1f` 拼起来（Anki 的约定）：

```
单词 | 释义 | 音标 | 例句 | 词性 | 备注 | 干扰项
```

- `sfld` = 单词；`csum` = `sha1(sfld)` 的前 8 位十六进制，和 Anki 的算法一致；
- `cards` 的 `ivl` / `factor` / `reps` / `lapses` / `due` / `type` / `queue` 跟着学习状态走：
  新卡 `type = queue = 0`，复习过的卡 `type = queue = 2`；
- `revlog` 的 `ease` 用 Anki 的语义：**1 = Again（答错或超时），3 = Good（答对）**；
  `time` 是反应毫秒；`ivl` / `lastIvl` 记新老间隔。

每次作答会**同时**写 Anki 的 revlog 和应用自己的 `wc_answer_log`。

## 标签与语言都存在 `notes.tags` 里

Anki 的标签本来就是「一条笔记可以有多个标签」，正好拿来放来源、语言和用户分类：

```
tags = ' 手动导入 lang::ja N2 第1课 '
         └ 来源    └ 语言      └ 用户标签
```

- 来源是 `手动导入` 或 `API 生成`；
- 语言是 `lang::en` / `lang::fr` / `lang::ja` / `lang::ko` / `lang::ru`；
- 用户标签写入前会把空白换成下划线（Anki 的标签不能带空格）；
- `lang::xx` 不会被当成用户标签，所以标签筛选里不会冒出语言。

这样拿 Anki 打开也能一眼看出这张卡是什么语言、打过什么标签。

## FSRS 的状态单独一张表

`wc_card_fsrs`（`uid` / `stability` / `difficulty` / `reps` / `lapses` / `state` / `last_review_at` / `due_at`）
与 `wc_card_stats`（掌握度、正确率、`interval_days`、`ease_factor`）**完全分开**：

- 开着 FSRS 时只写 `wc_card_fsrs`，原有那套字段照旧由原来的逻辑维护；
- 换回「原有算法」时 `wc_card_fsrs` 原样保留，不删不改；
- 卡片模型上就是 `WordCard.fsrs` 这个可空字段，读不出来就是 `null`（没进过 FSRS 调度）。

## 配置（`wc_settings`）

一条 JSON，`key = 'app_settings'`。里面的键：

| 键 | 含义 |
|---|---|
| `home_tab` | 上次停在哪个页面（存的是页面 id，不是下标） |
| `theme_mode` / `projection_theme_mode` | 主界面 / 演示模式各自的深浅色 |
| `active_deck_id` | 当前卡组 |
| `language` | 新词默认语言 |
| `quiz_question_count` | 每轮题数；**0 表示「全部」** |
| `study_tag_filter` | 作答范围里的标签筛选（多选取「与」） |
| `scheduler_mode` | 原有算法 / `fsrs` |
| `fsrs_desired_retention` | FSRS 目标保留率 |
| `prompt_template_id` | 上次用的 Prompt 模板 |
| `prefer_manual_mode` | 是否优先用网页聊天导入 |
| `api_*` | 地址 / 密钥 / 模型 / 超时 / 缓存时长 / 累计用量 |
| 演示相关 | 每题停留、编号样式、随机顺序、循环、每轮重排、提示音、答案文件模式与目录 |

旧库读不到这些键时各自有默认值，不需要迁移。

> 历史包袱：`quiz_question_count = 10` 曾经是「十题」的意思，后来「全部」也用它表示。
> 所以读到老设置块时会做一次性迁移：没有 `study_tag_filter` 键的旧块，
> `10` 被重新解释成「全部」，用户主动选过的 5 / 20 照旧尊重。保存过一次设置后这件事不会再发生。

## 从旧库迁移

早期版本用的是 sembast（`word_cards.db`）。启动时如果发现这个文件、
且新的 Anki 库里还没有卡片，就把卡片、答题记录、牌组、配置一次性搬过去，
然后把旧文件改名成 `word_cards.db.migrated`，不会重复导入。

`lib/src/data/local/` 下的 sembast 实现只为这次迁移保留。

## 与 Anki 互通

- **拿 Anki 打开**：把 `collection.anki2` 复制出来，用 Anki 的「文件 → 导入」或直接替换一个临时配置目录里的同名文件；
  新版 Anki 打开时会自动把 schema 11 升级成 18，**升级后就不要再拿回来给本应用用**；
- **从本应用导出**：导出页生成的是完整库文件（走 `VACUUM INTO`），可以直接给 Anki；
- **卡片 JSON** 用的是导入器认得的那套字段，所以「导出 → 再导入」是闭环的。
