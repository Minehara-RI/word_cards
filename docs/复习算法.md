# 复习算法

应用里有**两套挑选与排程算法**，在作答页的「复习算法」里二选一：

- **原有算法**：按正确率与掌握度挑词，间隔与 ease 存在 `wc_card_stats` 的字段里；
- **FSRS-6**：基于官方 `dart-fsrs` 包，记忆状态存在 `wc_card_fsrs` 表里。

两套**互不干扰**：开着 FSRS 只写它自己的表，换回原有算法时那张表原样留着，
谁也不覆盖谁。

## 原有算法

每个词按其历史表现更新一组字段（练习次数、正确率、掌握度、间隔天数、ease），
「只练做错过 / 正确率低的词」与「题目数量」都建立在这些字段上。
作答页的**标签筛选**只在选中它时出现 —— 挑选逻辑走的是按正确率排序的候选池，
和 FSRS 的到期队列不是一回事。

## FSRS-6

### 怎么接的

直接依赖 pub.dev 上的官方包 [fsrs](https://pub.dev/packages/fsrs)
（`open-spaced-repetition/dart-fsrs`，21 个参数即 FSRS-6）。
`lib/src/logic/fsrs.dart` 只有一层适配：**状态映射 + 评分映射 + 复习队列**，
公式一行都没有重写 —— 将来升级算法只要换包版本。

学习步长刻意留空（`learningSteps: []`）：本应用一轮里一个词只答一次，
不需要「1 分钟 / 10 分钟」这种当天内的学习步骤，首次作答后直接按稳定性给天数。

### 评分怎么来

作答结果映射到 FSRS 的 Again / Hard / Good / Easy：

| 情况 | 评分 |
|---|---|
| 答错，或超时未作答 | **Again** |
| 答对，用时 ≤ 40% 限时 | **Easy** |
| 答对，用时 ≤ 75% 限时 | **Good** |
| 答对，但更慢 | **Hard** |

所以**每题的限时直接影响评分**：限时设得太松，答对但慢的词会被判 Hard，间隔就短。

### 目标保留率

设置里可选 80% / 85% / 90% / 95%。它不影响「你的记忆长什么样」，
而是决定你愿意花多少时间：**调高 → 复习更勤、间隔更短**。

### 到期复习

打开 FSRS 后，作答页会在「只练做错过 / 正确率低的词」旁边多出一个
「复习今天到期的词（N）」，只挑今天真正到期的（含没学过的新词）。
这时标签筛选整块不画 —— 复习队列是按整个卡组排的，摆出来只会误导。

## 参数从哪来

用的是 dart-fsrs 包自带的默认参数（`kFsrs6DefaultParameters`）。
**不自己训练、也不抄别的应用的参数。**

想试别的参数集，给 `FsrsConfig(parameters: [...21 个...])` 传一组即可，
长度或格式不对会自动退回默认值。

## 为什么不做参数自优化

FSRS 的参数可以用你自己的复习历史拟合出来，但这件事有三个前提：

1. **数据量要够**：Anki 的门槛是几百条到 400 条复习记录；
2. **要用户主动触发**：Anki 里也没有后台自动优化，是用户在牌组预设里点一次「优化」，
   而且官方明确建议**不要抄别人的参数**、一个月优化一次就够；
3. **要一整套保护**：新参数在同一份数据上的 log loss 更差就不能采用，
   还要做体检（数据量门槛、交叉评估阈值）。

本应用目前的复习记录还远不到门槛，所以**不做自优化**，直接用官方默认参数。
等真实使用几个月、记录攒够了再考虑；真要接入，路线是先把 `fsrs-rs` 的
`compute_parameters` 编成动态库（FFI），而不是用 Dart 重写训练循环 ——
训练循环里的正则、退火、冻结、裁剪细节很多，重写容易「像但不是」。
