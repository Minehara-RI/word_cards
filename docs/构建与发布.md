# 构建与发布

一句话：**跑 `scripts\build_release.ps1`**，产物全在 `dist\`。

## 产物清单

| 文件 | 给谁 | 怎么用 |
|---|---|---|
| `dist\word_cards-<版本>.apk` | 安卓手机 | 传到手机点开装（需要允许「安装未知来源应用」） |
| `dist\word_cards-setup-<版本>.exe` | Windows 电脑 | 双击安装，带开始菜单与可选的桌面快捷方式、可卸载 |
| `dist\word_cards-win-x64.zip` | 不想装东西的人 | 解压直接跑 `word_cards.exe` |
| `dist\word_cards-win-x64\` | 同上的目录版 | 免安装 |

`<版本>` 来自 `pubspec.yaml` 的 `version:`，打包脚本自己读，不用手改；
要发新版就改 `pubspec.yaml` 再重跑。

`dist\` **不进版本库**（见 `.gitignore`），发布时作为 release 附件上传。

## 一条命令

```powershell
pwsh -File scripts\build_release.ps1
```

它按顺序做四件事：

1. `scripts\verify.ps1` —— `flutter analyze` + `flutter test` + Windows 集成测试，最后重建 Debug exe；
2. `scripts\build_apk.ps1` —— release APK；
3. `scripts\build_windows.ps1` —— release 免安装目录 + zip；
4. `scripts\build_installer.ps1` —— 用 Inno Setup 打成单文件安装包。

赶时间可以跳步：`-SkipVerify`（不跑测试）、`-SkipInstaller`（不出安装包）。

## 脚本

| 脚本 | 作用 |
|---|---|
| `env.ps1` | 设置工具链路径，其它脚本都 dot-source 它 |
| `verify.ps1` | analyze + 单元测试 + 集成测试 + 重建 Debug exe；`-SkipIntegration` 只跑前两步 |
| `build_apk.ps1` | 出 release APK；`-Split` 出三个分 ABI 的包 |
| `build_windows.ps1` | 出免安装目录与 zip；`-Installer` 顺带打安装包 |
| `build_installer.ps1` | 只打 Inno Setup 安装包 |
| `build_release.ps1` | 上面几个串起来一次出齐 |

## 工具链路径

全部集中在 `scripts\env.ps1`，取值顺序是：

1. 环境里已经设好的同名变量（`FLUTTER_ROOT` / `JAVA_HOME` / `ANDROID_HOME` / `PUB_CACHE` / `GRADLE_USER_HOME`）；
2. 脚本里的默认路径；
3. PATH 上的 `flutter`。

每一项都要「里面确实有对应的文件」才算数，找不到会直接报错，
免得后面报一堆看不懂的构建错误。换机器改这一个文件即可。

另外两样是系统级安装的，脚本会自动找：

- **Inno Setup 6** —— 打 Windows 安装包用。
  常见位置是 `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`，装在 `Program Files` 也认；
  没装的话加 `-SkipInstaller`，只出免安装 zip。
- **Android NDK** —— `sqlite3_flutter_libs` 要编译原生库。

> 不想把工具链装到默认位置，就先设好上面那几个环境变量再跑脚本。

## Android

- **包名** `com.minehara.word_cards`；`minSdk` / `targetSdk` 用 Flutter 的默认值（见 `android\app\build.gradle.kts`）。
- **签名**：`release` 目前用的是 **debug 签名**（Flutter 模板原样）。
  它是合法签名，自己装、发给朋友都够用，只是不是上架应用商店的那种。真要上架：

  ```powershell
  keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
  ```

  然后在 `android\key.properties` 里写路径与口令（这两样已在 `.gitignore` 里，不会入库），
  最后把 `build.gradle.kts` 的 `signingConfig` 换成读 `key.properties` 的 `release` 配置。
- **通用包 58 MB 是正常的**：里面带了 `arm64-v8a` / `armeabi-v7a` / `x86_64` 三个 ABI 的 SQLite 原生库。
  只装自己手机想要小一点，用 `-Split` 出三个分 ABI 的包，装对应那个（通常 20 MB 上下）。

## Windows

- 产物是 **x64、release** 构建。
- **按用户安装，不弹 UAC、不要管理员密码**（Inno Setup 的 `PrivilegesRequired=lowest`，
  于是 `{autopf}` 映射到 `%LOCALAPPDATA%\Programs`），装到：

  ```
  C:\Users\<你>\AppData\Local\Programs\word_cards
  ```

  装完从开始菜单（「单词卡片」）启动。想装给全机器用可以自己加 `/ALLUSERS`
  （已开 `PrivilegesRequiredOverridesAllowed=commandline`）。
- **卸载不碰用户数据**：数据在 `%APPDATA%\com.minehara\word_cards\collection.anki2`，
  `[UninstallDelete]` 只清安装目录里的 `data\`。
- 安装界面是**简体中文**，但官方 Inno Setup 不自带中文语言文件 ——
  `packaging\word_cards.iss` 里用 `#if FileExists(...ChineseSimplified.isl)` 判断：
  装了语言包就出中文，没装自动退回英文，**不会因此编译失败**。
- 应用图标取 `windows\runner\resources\app_icon.ico`。

## 目录约定

```
scripts\                 打包与体检脚本（入版本库）
  env.ps1                工具链路径，唯一需要按机器改的文件
packaging\               安装包定义（入版本库）
  word_cards.iss         Inno Setup 脚本
dist\                    产物（不入版本库）
```

## 常见问题

**Gradle 下载引擎产物时 `Connect to 127.0.0.1:7897 failed: Connection refused`**

本机的 Gradle 走一个本地代理（配置在用户目录的 `gradle.properties` 里，不在仓库里）。
代理没开时，release 构建会在下载 `io.flutter:arm64_v8a_release` 这类产物时失败。两个办法：

- 把代理打开（推荐）；
- 或者临时注释掉那几行代理配置 —— 但**必须先把 Gradle 守护进程停掉**：

  ```powershell
  cd android; .\gradlew.bat --stop; cd ..
  ```

  Gradle 的 `systemProp.*` 是守护进程启动时固化的，**光改文件不重启守护进程等于没改**。

**`Target build_hooks failed: Building native assets failed`**

Android 构建要联网下载 sqlite3 的原生库，没走代理就会这样；清过 `.dart_tool\hooks_runner` 之后第一次构建一定会遇到。

**跑完集成测试后手动打开应用，看到的是测试界面**

集成测试会把 `build\windows\...\word_cards.exe` 换成测试宿主。
`verify.ps1` 跑完会自动 `flutter build windows --debug` 重建；单独跑集成测试的话要自己补一次。

## 发布前自查

1. `pubspec.yaml` 的 `version:` 改好了吗（它决定产物文件名与安装包版本）；
2. `pwsh -File scripts\build_release.ps1` 全绿；
3. 手机上装 APK，跑一遍「加入 → 作答 → 统计 → 导出」；
4. 电脑上装安装包，跑一遍同样的四页 + 演示页；
5. `dist\` 里的东西不进版本库，作为 release 附件上传；
6. 更新 [CHANGELOG.md](../CHANGELOG.md)。
